title: HTML 的风能吹多久
author: 吴诗涛
date: '2026-08-06'

---

最近，职场里用 HTML 做演示的人越来越多了。

AI 普及之后，很多人不再打开 PowerPoint，而是让 AI 直接生成一个 HTML 页面当演示文稿用。

仔细想想，这确实有它的道理：AI 生成 HTML 几乎没有门槛，动画、配色、排版信手拈来；浏览器打开就是成品，跨设备、可分享，效果往往比套模板的 PPT 更酷炫。

其实我一度认为用 HTML 做演示是对的。在 AI 出现之前，我也已经用 [Quarto](https://quarto.org/) 制作 HTML 的文档了。

但最近 HTML 演示看得多了，慢慢发现两个问题。

第一个问题，是大部分 HTML 的信息密度太低。

很多人是基于已有整理好的文档，让 AI 生成 HTML。成品洋洋洒洒十几二十页，演示的时候确实好看，但真的想要从中获取有效信息，还不如直接把用来生成 HTML 的那份文档拿出来看一下。

第二个问题，是多数人没有直接编辑 HTML 的能力。

对会用的人来说，HTML 是灵活的；对不会的人来说，它只是一堆代码。于是整个过程变成了：让 AI 生成，看一眼，不满意，再让 AI 改，直到「哦，差不多了，就这个吧」。

当制作和修改都只能交给 AI，人剩下的工作就只是验收。验收代替了创作，作品自然充满妥协。

于是出现了一个很尴尬的现象：AI 原本降低了制作演示的门槛，却让使用者离内容更远了。这让我想到 Office 三剑客「所见即所得」的能力对大部分职场人是很必要的。

对于我自己，这些年越来越习惯阅读和使用纯文字、有结构的文档，它最扁平、最方便。

从大学搭博客开始，我就用 Markdown 写东西。标题、列表、引用、链接，都是符号标记出来的纯文本，没有任何布局代码。想改哪里改哪里，想搜什么搜什么，随时可以复制、转成别的格式。一篇文章，几十行文字就是全部，信息密度很高。

在这个一切都在加速生成的时代，真正重要的，还是信息如何流动，以及人能不能直接上手操作。

现在 WorkBuddy 已经推出「人机双写」，演示载体又回到了 PPT，支持 AI 和人一起修改文件。

所以，这股 HTML 的风还能吹多久？

我想，HTML 作为演示的载体，应该还会存在很久；但让 AI 生成 HTML 的这种工作方式，未必会一直流行下去。用户最终会做权衡，用脚投票。
